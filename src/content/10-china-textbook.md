> **【一言蔽之】**  
> 把它想成一座没有前台的市立图书馆。馆里确实有小学到大学的课本，而且不收费；但门口没有电梯，书是一箱箱 PDF，有的还被拆成 `.pdf.1`、`.pdf.2` 才能塞进 GitHub。你要是把整栋楼搬回家，硬盘会先投降，AI 也读不懂那些二进制箱子。正确用法是：先看目录卡，只借你要的那一本，再把文字誊到笔记本上给 AI 翻。

## 🔬 一、 核心原理解析 (理解层)

[TapXWorld/ChinaTextbook](https://github.com/TapXWorld/ChinaTextbook) 做的事情非常朴素：**把国内已经公开过的中小学、大学 PDF 教材集中放到 GitHub 上**，方便找、方便下，也方便身在海外的家庭还能摸到国内课本。

它不是一个 App，没有网站后台，也几乎没有“功能代码”。你看到的星星，是冲着“课本被集中、被公开”去的。

作者自己写的由来大概是两层：

- 国内其实有免费渠道，但普通人不好找；有人把这些 PDF 打上私人水印再拿去卖。这个仓库想把资源摊开。
- 更在意海外华人孩子还能对上国内的教学内容。

仓库按学段 / 学科 / 版本摊开，例如 `小学/数学/人教版/`、`大学/高等数学/`。GitHub 单文件超过 50MB 会报警、超过 100MB 会拒收，所以大书被切成大约 35MB 一份的 `.pdf.1`、`.pdf.2`。官方工具只是按顺序把这些碎片 **二进制拼接** 回去，并不是什么 PDF 编辑器。

硬数据也值得心里有数：大约 **2000 册、43GB**。这就是为什么“配置到电脑上”绝对不等于 `git clone` 整库。

## 🛠️ 二、 工程实践指南 (实践层)

本站仓库里已经放了一套本地工具，专门解决三件事：**找书、按需下载、抽成 AI 能搜的 Markdown**。

```bash
python3 tools/china-textbook/cli.py list --query "线性代数"
python3 tools/china-textbook/cli.py prepare --query "线性代数" --ocr --pages 1-20
python3 tools/china-textbook/cli.py search "特征值"
```

`prepare` 会做完下载、合并分卷、按 15 页切成 `textbook/text/.../p0001-0015.md`。这个库里很多课本是拍照/扫描的，PDF 里没有文字层；**不加 `--ocr`，AI 只能看到空页**。PDF 和抽取正文都留在被 git 忽略的 `textbook/` 里，不会发到网站上。

给 AI 的阅读规矩也很死：

1. 先查 `tools/china-textbook/data/catalog.md`，不要问它“仓库里有没有某某书”却让它去翻 43GB。
2. 只 `prepare` 当前要读的那一册。
3. 先打开该书目录下的 `README.md`，再按页码读分片。
4. 禁止直接 Read PDF。扫描件抽不出字时，老老实实说抽不出，不要脑补课文。

更完整的说明在 `tools/china-textbook/README.md`，Cursor 规则在 `.cursor/rules/china-textbook.mdc`。

## 💡 三、 避坑与进阶 (升华层)

- **最大的坑**：把 ChinaTextbook 整库克隆进 Cursor。索引会很痛，对话上下文更痛，而且 PDF 本来就不是给语言模型准备的格式。
- **第二坑**：以为 `extract` 完就等于读过书。不少教材是扫描件，没有文字层。先 `--ocr --pages 1-20` 试几页，确认中文能认，再决定要不要抽全书。OCR 会读错字，公式尤其容易糊。
- **版权边界**：清单可以公开备份，方便检索；课文本身请留在自己电脑里个人学习，不要重新上传、不要贴到这个公开网站。
- **和“智能题库产品”的差别**：这套流程不生产新题，也不替代课堂。它只是把已经公开的课本，变成 AI 能按页检索的本地语料。
